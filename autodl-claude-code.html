为什么要这样做？

很多朋友买了 AutoDL 云 GPU 服务器做深度学习，本地用着 Claude Code 写代码很爽，于是也在服务器上装了 Claude Code，结果发现——根本连不上 API。

然后你开始搜教程：有人在服务器上装 Clash、配 HTTP_PROXY 环境变量、设端口转发……折腾一下午终于跑通，结果服务器重启一下，代理又挂了。

关键认知：Claude Code 本质上是一个命令行客户端。它把你的需求发给 Anthropic 的 API，再把 API 返回的结果展示给你。API 请求从哪台机器发出，Claude Code 就必须在哪台机器上运行。
场景API 请求路径结果
本地电脑有代理 / 国内直连你的电脑 → API 服务器✅ 通
AutoDL 服务器没代理服务器 → API 服务器（被墙）❌ 不通

换个思路：让 Claude Code 继续在你本地跑（API 走本地网络），但通过 SSH 让它操作远程服务器。它能在远程读写文件、执行命令、调用 GPU，而 API 请求压根没经过远程服务器。

这就是本教程的全部核心。理解这一点，后面都是操作细节。

准备工作

开始之前，请确认以下条件：

  1. 本地 Claude Code 已能正常使用——能正常跟它对话就行
  2. AutoDL 服务器已开机——拿到 SSH 连接信息（IP、端口、用户名）
  3. 本地是 Windows 系统——本教程基于 Windows 11 + PowerShell，macOS/Linux 会更简单

AutoDL 的 SSH 连接信息长这样（在你租用实例的控制台页面可以找到）：

SSH 命令：ssh -p 42144 root@connect.cqa1.seetacloud.com
端口：42144
用户名：root
主机：connect.cqa1.seetacloud.com

第一步：在本地生成 SSH 密钥

SSH 密钥就像一把钥匙和一把锁。你把「公钥」（锁）放在服务器上，自己留着「私钥」（钥匙）。连接时服务器用公钥验证你是私钥的持有者，不需要每次都输密码。

打开本地终端：按键盘上的 Win + R，输入 powershell，回车。

在 PowerShell 中输入以下命令：

ssh-keygen -t ed25519

你会看到三个提示，全部直接按回车即可：

Generating public/private ed25519 key pair.
Enter file in which to save the key (C:\Users\你的用户名/.ssh/id_ed25519):   ← 直接回车
Enter passphrase (empty for no passphrase):                                   ← 直接回车（不设密码）
Enter same passphrase again:                                                  ← 再回车一次
说明：ed25519 是最新的密钥算法，比老的 RSA 更快更安全。不设密码是为了让 Claude Code 能自动连接，不需要你每次手动输入。

完成后，你的密钥文件位于：

C:\Users\你的用户名\.ssh\
├── id_ed25519      ← 私钥（留在本地，绝对不要发给别人）
└── id_ed25519.pub  ← 公钥（放到服务器上）

第二步：把公钥上传到 AutoDL 服务器

这是最容易踩坑的一步。Windows 下有好几种方法，但大部分都会失败。我把自己踩过的坑列出来，你可以直接跳到最后的可行方案。

❌ 踩坑记录（可以跳过）

失败 1：在 Claude Code 里直接 SSH

! ssh -p 42144 root@connect.cqa1.seetacloud.com

失败原因：Claude Code 的 Bash 工具没有交互式终端（TTY），无法输入密码。报 Permission denied。

失败 2：用 sshpass 自动输密码

sshpass -p '你的密码' ssh -p 42144 root@connect.cqa1.seetacloud.com

失败原因：Windows 根本没有 sshpass 这个命令。

失败 3：用 ssh-copy-id

ssh-copy-id -p 42144 root@connect.cqa1.seetacloud.com

失败原因：Windows PowerShell 没有 ssh-copy-id，即使用 Git Bash 也有同样的问题——它需要交互式输入密码。

失败 4：PowerShell 一行命令管道

type $env:USERPROFILE\.ssh\id_ed25519.pub | ssh -p 42144 root@connect.cqa1.seetacloud.com "mkdir -p ~/.ssh && cat >> ~/.ssh/authorized_keys"

失败原因：PowerShell 把 >> 解析坏了，服务器端报语法错误。

✅ 可行方案：scp + ssh 两步走

核心思路：先用 scp（SSH 文件传输）把公钥传到服务器，再连上服务器手动写入。每一步都要输入密码，但不会卡在交互式 TTY 上。

第 1 小步：用 scp 上传公钥文件

在 PowerShell 中执行（注意：scp 的端口参数是大写 -P）：

scp -P 42144 $env:USERPROFILE\.ssh\id_ed25519.pub root@connect.cqa1.seetacloud.com:/tmp/

系统会提示你输入密码（AutoDL 控制台可以看到 root 密码），输入后回车。看到传输进度条就说明上传成功。

第 2 小步：连上服务器，把公钥写入 authorized_keys

ssh -p 42144 root@connect.cqa1.seetacloud.com "mkdir -p ~/.ssh && cat /tmp/id_ed25519.pub >> ~/.ssh/authorized_keys && chmod 600 ~/.ssh/authorized_keys"

再输一次密码。这条命令做了三件事：

  1. mkdir -p ~/.ssh —— 创建 .ssh 目录（如果已存在则跳过）
  2. cat /tmp/id_ed25519.pub >> ~/.ssh/authorized_keys —— 把公钥内容追加到授权文件
  3. chmod 600 ~/.ssh/authorized_keys —— 设置权限（SSH 要求只有文件所有者能读写）
总结：你的公钥现在已经在服务器的 ~/.ssh/authorized_keys 里了。以后 SSH 连接时，服务器会用这个公钥验证你的身份，不再需要密码。

第三步：验证免密登录

在 PowerShell 中测试免密连接：

ssh -p 42144 root@connect.cqa1.seetacloud.com "echo 连接成功！ && hostname && uname -a"

如果成功，你会看到类似这样的输出（不用输密码）：

连接成功！
autodl-container-508440a921-2f6c65c5
Linux autodl-container 5.15.0 #1 SMP x86_64 GNU/Linux
如果还是提示输入密码：检查 ~/.ssh/authorized_keys 文件是否有正确的权限。连上服务器执行 chmod 600 ~/.ssh/authorized_keys && chmod 700 ~/.ssh 然后重试。

第四步：用 Claude Code 连接远程服务器

现在密钥配好了，打开 Claude Code，直接对它说：

帮我连接上这台 SSH 服务器：
ssh -p 42144 root@connect.cqa1.seetacloud.com

因为已经免密，Claude Code 可以直接通过 Bash 工具连上。它会告诉你连接成功，并且列出服务器的基本信息：

已成功连接！服务器信息：
• 主机名：autodl-container-508440a921-2f6c65c5
• 系统：Ubuntu 22.04，x86_64，Linux 5.15.0
• GPU：NVIDIA GeForce RTX 4090 D，24GB VRAM（1 卡）
• 内存：~1TB 总，~944GB 可用
• 磁盘：30GB（已用 1.3GB）

此时 Claude Code 已经「身处」远程服务器了。它能读写远程文件、执行远程命令、用远程 GPU 跑训练。但 API 请求依然走你的本地网络——代理问题根本不存在。

第五步：连上之后怎么用？

第一次对话：先交代环境

连接成功后，让 Claude Code 了解它现在操作的是远程环境：

你现在通过 SSH 连在一台 AutoDL 远程服务器上。
系统：Ubuntu 22.04
Python：3.10
CUDA：12.1
磁盘空间：30GB
GPU：RTX 4090D（24GB）

请先确认环境是否正确，然后帮我做以下事情：
1. 检查是否已安装 PyTorch（能用 CUDA 的版本）
2. 如果没装，用 conda 安装 PyTorch 2.x + CUDA 12.1
3. 装好后跑 nvidia-smi 确认 GPU 可用

完整任务示例：训练模型

帮我完成以下操作：
1. cd /root 然后 git clone https://github.com/xxx/my-project.git
2. 阅读 README.md 了解项目
3. 用 pip 安装 requirements.txt（下载慢就换清华源）
4. 运行 python train.py --epochs 5 --batch_size 32
5. 训练结束后告诉我最终的 loss 和 accuracy
6. 把训练日志、模型权重存到 /root/output/ 目录

Claude Code 会逐步执行，中间遇到报错它会自己排查。比如 pip 下载超时，它会主动换清华镜像源；CUDA 版本不对，它会重装对应版本。

常用操作速查

你想做的事对 Claude Code 这样说
查看 GPU 状态帮我看下 nvidia-smi，GPU 有没有被占用
安装深度学习环境装 PyTorch 2.3 + CUDA 12.1，用 conda 装，如果慢换清华源
运行训练跑 python train.py，把 stdout 和 stderr 都存到 /root/logs/train.log
下载数据集从 https://xxx.com/data.zip 下载数据集到 /root/data/，如果太大用 aria2c 多线程下载
调试错误报错了：RuntimeError: CUDA out of memory. 帮我分析原因并优化 batch size 或梯度累积
查看训练进度帮我看 /root/logs/train.log 最后 30 行，分析当前的 loss 趋势

第六步：用 tmux 保持任务不中断（重要）

AutoDL 的 SSH 连接可能因为网络波动断开——如果你正在跑训练，断开意味着任务中断，半天白等。

tmux 就像一个「后台房间」：你把任务放进去，然后你可以离开（断开连接），过段时间回来（重连），任务还在跑。

安装和基本使用

# 在服务器上安装 tmux
sudo apt update
sudo apt install tmux -y

# 创建一个新的 tmux 会话（起个名字好找）
tmux new -s training

# 在这个 tmux 会话里，运行你的训练
python train.py --epochs 100

# 按 Ctrl+B 然后按 D  —— 你会退出 tmux，但训练继续在后台跑

# 断开 SSH 也没关系，训练不会停。下次连上服务器后：
tmux attach -t training    # 恢复之前的 tmux 会话，看到你的训练还在跑
你需要的操作命令
新建会话tmux new -s 名字
后台挂起先按 Ctrl + B，松开后按 D
重新进入tmux attach -t 名字
查看所有会话tmux ls
关闭会话在 tmux 里输入 exit 或按 Ctrl + D
上下滚动看历史先按 Ctrl + B，松开后按 [（然后用方向键翻页，按 q 退出）
好习惯：凡是运行时间超过 5 分钟的任务（训练、下载大数据集），一律在 tmux 里跑。多花 10 秒，省你几小时重跑。

进阶技巧

pip / git 下载慢？用国内镜像

# pip 清华源（推荐，带宽大）
pip install -i https://pypi.tuna.tsinghua.edu.cn/simple 包名

# 永久设置 pip 镜像（不需要每次加 -i）
pip config set global.index-url https://pypi.tuna.tsinghua.edu.cn/simple

# Git 克隆慢也可以用镜像
git clone https://ghproxy.com/https://github.com/xxx/repo.git

把 SSH 信息存到文件里，让 Claude 自己读

在项目根目录创建 host.md 文件：

# 远程服务器
SSH命令：ssh -p 42144 root@connect.cqa1.seetacloud.com
别名：4090-server
GPU：RTX 4090D × 1
OS：Ubuntu 22.04

然后直接说：

请读 host.md，连上 4090-server

同样的方法适用其他 AI 编程工具

工具方式
OpenAI Codex CLI本地跑客户端，SSH 连远程
GitHub Copilot CLI同上
Cursor / Windsurf本地连 API，Remote SSH 插件操作远程文件
Google Gemini CLI本地跑，远程执行

本质不变：客户端在哪跑，API 请求就从哪出。只要本地网络能访问 API，远程服务器就不需要任何代理配置。

常见问题排查

你遇到的问题可能原因怎么解决
Host key verification failed 第一次连这台服务器，SSH 要你确认指纹 先在 PowerShell 里手动 ssh -p XXXX user@host 一次，输入 yes
Permission denied (publickey,password) 密钥没配好 回到第二步，重新走一遍 scp + ssh 流程
pip install 超时 / 极慢 默认 PyPI 源在海外 加 -i https://pypi.tuna.tsinghua.edu.cn/simple
git clone 卡住不动 GitHub 国内直连慢 用 ghproxy.com 代理或在 Claude Code 里让它重试
跑着跑着 SSH 断了，训练没了 网络波动导致连接断开 下次记得用 tmux！所有长时间任务必须在 tmux 里跑
scp 报 invalid port 用了小写 -p scp 的端口参数是大写 -P（ssh 是小写 -p）
服务器磁盘满了 数据集 / 模型权重太多 df -h 检查；du -sh /root/* 看谁占空间；清理不需要的文件

总结

回到最初的问题：怎么在 AutoDL 上用 Claude Code？

答案不是「在服务器上装代理」，而是——Claude Code 留在本地，用 SSH 连过去。

远程开发很多问题都是这样，想清楚「谁在调 API、谁在执行命令」，就不会绕弯路。

全程回顾：

  1. 本地生成 SSH 密钥：ssh-keygen -t ed25519
  2. scp + ssh 两步上传公钥到服务器
  3. 验证免密登录
  4. Claude Code 里让 AI 连服务器
  5. 交代清楚环境，开始干活
  6. 长时间任务记得用 tmux
