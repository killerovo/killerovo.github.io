0. 为什么远程服务器用不了 Claude Code？

很多朋友在 AutoDL 上做远程开发，本地 VSCode 里用着 Claude 插件很爽，自然也想在远程环境用上 AI 编程助手。结果装上去发现：API 连不上。

网上搜一圈，说要在服务器上装代理——clash、配端口、设 HTTP_PROXY 环境变量，折腾半天好不容易跑通，重启服务器又失效了。

方向就错了。为什么非要在服务器上装 Claude Code？你本地不是用得好好的吗？

核心原因

Claude Code 本质上是一个命令行客户端——你在终端里跟它对话，它把你的需求发给 API。关键在于：API 请求从哪里发出，Claude Code 就在哪里跑。

场景API 请求路径结果
本地电脑有代理API 请求走代理✅ 通
远程服务器没代理API 请求直连海外❌ 不通

换个思路： 让 Claude Code 在本地跑，通过 SSH 操作远程服务器。API 请求走本地网络，问题根本不存在。

1. 配置 SSH 密钥免密登录（踩坑全记录）

1.1 先在本地终端生成密钥

打开本地终端（PowerShell / cmd / Git Bash），生成 SSH 密钥：

ssh-keygen -t ed25519

一路回车即可（默认路径 ~/.ssh/id_ed25519，无需设密码）。

1.2 把公钥上传到 AutoDL 服务器

这一步是踩坑最密集的地方，以下列出各种尝试及最终方案。

⚠️ 踩坑记录：以下方法在 Windows 环境都会失败，可以直接跳到最终方案。

❌ 方法一：Claude Code 里直接 ! ssh

! ssh -p 42144 root@connect.cqa1.seetacloud.com

失败原因： Claude Code 的 Bash 工具没有交互式 TTY，无法输入密码。报错 Permission denied (publickey,password)。

❌ 方法二：用 sshpass

sshpass -p '密码' ssh -p 42144 root@connect.cqa1.seetacloud.com

失败原因： Windows 没有 sshpass 命令。

❌ 方法三：ssh-copy-id

ssh-copy-id -p 42144 root@connect.cqa1.seetacloud.com

失败原因： Windows PowerShell 没有 ssh-copy-id 命令。即使手动安装，它同样需要交互式输入密码，Bash 工具没有 TTY。

❌ 方法四：PowerShell 管道一行命令

type $env:USERPROFILE\.ssh\id_ed25519.pub | ssh -p 42144 root@connect.cqa1.seetacloud.com "mkdir -p ~/.ssh && cat >> ~/.ssh/authorized_keys"

失败原因： PowerShell 把 >> 解析坏了，报 syntax error near unexpected token 'newline'。

✅ 最终方案：scp + ssh 分两步

第一步：用 scp 上传公钥

在本地 PowerShell 里执行（注意 scp 用大写 -P 指定端口）：

scp -P 42144 $env:USERPROFILE\.ssh\id_ed25519.pub root@connect.cqa1.seetacloud.com:/tmp/

输入密码后，公钥文件就传到了服务器的 /tmp/ 目录。

第二步：SSH 进去把公钥写入 authorized_keys

ssh -p 42144 root@connect.cqa1.seetacloud.com "mkdir -p ~/.ssh && cat /tmp/id_ed25519.pub >> ~/.ssh/authorized_keys && chmod 600 ~/.ssh/authorized_keys"

再输一次密码即可完成配置。

1.3 验证免密登录

配置完成后，试试免密连接：

ssh -p 42144 root@connect.cqa1.seetacloud.com "echo CONNECTED && hostname && uname -a"

如果能直接看到服务器的主机名和系统信息，说明密钥配置成功。

2. 用 Claude Code 连接远程服务器

2.1 前提条件

  • ✅ 本地 Claude Code 能正常使用
  • ✅ SSH 密钥已配置，可以免密登录
  • ✅ AutoDL 服务器已开机，拿到 SSH 连接信息

2.2 直接在 Claude Code 中连接

在 Claude Code 中输入：

帮我连接上这台 SSH 服务器：ssh -p 42144 root@connect.cqa1.seetacloud.com

由于已经配置了免密登录，Claude Code 可以直接通过 Bash 工具连上服务器。

连接成功后的环境确认示例：

服务器信息：
- 主机名： autodl-container-508440a921-2f6c65c5
- 系统： Ubuntu，x86_64，Linux 5.15.0
- GPU： NVIDIA GeForce RTX 4090 D, 24GB VRAM
- 内存： ~1TB 总，~944GB 可用
- 磁盘： 30GB（已用 1.3GB）

此时 Claude Code 已经「身处」远程服务器——它能读写远程文件、执行远程命令、调用远程 GPU，但 API 请求依然走本地网络。

3. 连上之后怎么用？

3.1 第一句话交代环境

告诉 Claude Code 它现在操作的是什么环境，避免误判：

你现在在一台 AutoDL 服务器上，Ubuntu 系统，已安装 Python 3.10 和 CUDA 12.1。请帮我把 /root/my-project 目录下的项目跑起来。

3.2 一个完整的任务示例

帮我完成以下操作：

1. 克隆仓库 https://github.com/xxx/my-project.git
2. 安装 requirements.txt 中的依赖
3. 运行 python train.py --epochs 5
4. 训练完成后告诉我最终的 loss 和 accuracy

Claude Code 会逐步执行，中间遇到报错还会自己排查——比如 pip 安装超时，它会主动尝试换国内镜像源。

3.3 常见操作

场景提示词示例
查看 GPU 状态帮我看下 GPU 使用情况
安装环境帮我装 Python 3.10 + CUDA 12.1 + PyTorch
运行实验跑 python train.py，把日志存到 /root/logs/
下载数据集下载 xxx 数据集到 /root/data/，太大的话用 aria2c
代码调试报错 CUDA out of memory，帮我优化一下 batch size

4. 进阶技巧

4.1 用 tmux 后台运行，断开也不怕

AutoDL 的 SSH 连接可能因为网络波动断开，用 tmux 把任务放到后台运行：

# Ubuntu 安装 tmux
sudo apt update
sudo apt install tmux -y

# 启动 tmux
tmux

tmux 三命令速记：

操作命令
新建会话tmux new -s 名字
后台挂起Ctrl + B 松开后按 D
重新进入tmux a -t 名字

4.2 pip / git 下载慢

让 Claude Code 配国内镜像源：

pip install -i https://pypi.tuna.tsinghua.edu.cn/simple 包名

4.3 把 SSH 信息存到文件

把 SSH 连接信息写到一个文件（如 host.md），然后让 Claude 自己读：

请阅读 host.md 文件，然后登录远程服务器

4.4 同样的思路适用于其他 AI 工具

工具原理
OpenAI Codex / GitHub Copilot CLI本地跑客户端，SSH 连远程操作
Google Gemini CLI同上，本地跑客户端，远程跑代码
Cursor / Windsurf本地连 API，通过 Remote SSH 操作远程文件

本质： 客户端在哪跑，API 请求就从哪出。只要本地网络能访问 API，远程服务器就不需要任何代理配置。

5. 常见问题

问题原因解决
Host key verification failed SSH 首次连接需确认指纹 先在本地终端手动 SSH 一次，输入 yes 确认
Permission denied 密钥未正确配置 重新按「最终方案」走 scp + ssh 两步
pip 安装超时 默认 PyPI 源慢 让 Claude 换清华源 -i https://pypi.tuna.tsinghua.edu.cn/simple
git clone 慢 GitHub 直连慢 让 Claude 换镜像或配置代理
SSH 断开，任务中断 网络波动 使用 tmux 把任务放后台
权限不够 非 root 操作受限 提醒 Claude 用 sudo（AutoDL 默认 root 用户一般不会遇到）

总结

回到最初的问题：怎么在 AutoDL 上用 Claude Code？

答案不是「在服务器上装代理」，而是换个方向——Claude Code 留在本地，用 SSH 连过去。

远程开发很多问题都是这样，想清楚「谁在调 API、谁在执行命令」，就不会绕弯路。

核心步骤回顾：

  1. 本地生成 SSH 密钥：ssh-keygen -t ed25519
  2. 上传公钥（Windows 用 scp + ssh 两步法）
  3. Claude Code 里直接让 AI 连接服务器
  4. 交代环境，开始干活
